# 决赛海报（一页英文）

赛题"六、其它"要求：进入决赛的自主选题队伍须按 AMD 提供的 PPT 模板提供**一页英文 PPT 海报**
作为作品简介，**不包含队伍信息**，用 **A4 纸彩色打印**带到决赛现场。

本目录是这份海报的**内容稿**。

| 文件 | 说明 |
|---|---|
| `one_page_poster.pptx` | 海报本体（一页，英文，**不含任何队伍信息**） |
| `make_poster.py` | 生成脚本（改内容后重跑即可） |
| `preview/page-0001.png` | 渲染预览（用于确认排版） |

## 1. 打印

页面是 pptx 默认的 **4:3（25.4 × 19.05 cm）**。打印到 A4 时在打印对话框选择
**"缩放以适应纸张"**即可铺满。

> 为什么不用 A4 页面尺寸：把 `slide_width/height` 改成 A4 而模板的母版仍是 4:3 时，
> 渲染器会把所有坐标放大约 1.27 倍，正文会越出右边界、最后几节掉出页面底部。
> 用默认页面尺寸时，渲染与文件中的几何一致。

---

## 2. ⚠️ 关于渲染器差异（如实说明）

本海报是在 **LibreOffice** 下渲染核对的（本机可用的渲染器）。
实测：同一份文件，该渲染器实际使用的换行宽度与纵向坐标约为文件中设定值的 **1.25–1.28 倍**
（在 6 / 10 / 12 / 14 / 18 cm 的测试文本框上都成立，且与所选字体无关）。

**这带来的后果**：

| 渲染器 | 结果 |
|---|---|
| **LibreOffice**（本目录 `preview/` 的来源） | 排版正确、无溢出——因为字号与列宽已按这个放大倍数保守设计（正文 6 pt、列宽 6.5 cm） |
| **Microsoft PowerPoint** | 会按 1.0 倍排版，因此内容比本预览**更紧凑、更靠上**，底部会留出一些空白 |

**两方面都不会出现内容被裁切**，这是这次刻意保守设计的取舍结果：
宁可让 PowerPoint 里底部留白，也不让任何一版把文字切掉。

> 本项目的 `report/design_report.md` 与 `skill/` 里记录的同类经验是：
> **凡是"看起来成功了"的地方都要用端到端的证据验证，不要相信状态字段。**
> 这里同样适用 —— 排版不能靠"设了宽度就应该在宽度内换行"这个假设，
> 而要靠渲染出来量一次。

## 3. 套用官方模板

赛事方的 PPT 模板发布后，按下面步骤迁移：

1. 打开官方模板，保留其版式与配色；
2. 本海报的内容分五块，直接对应复制：
   - 标题 + 副标题（`WHY THIS` 之上）
   - **WHY THIS, AND WHAT IS HARD ABOUT IT**（问题与动机）
   - **SYSTEM ARCHITECTURE**（含 ASCII 数据流图，注意保持等宽字体）
   - **MEASURED RESULTS**（表格，7 行）
   - **PERFORMANCE: 2.4 -> 7.5 fps, ZERO HW COST**
   - **TWO HARD PROBLEMS, DIAGNOSED READ-ONLY**
   - **HOW CORRECTNESS IS ESTABLISHED**
3. **删掉一切队伍信息**（本稿本来就没有，迁移时注意不要带上）；
4. 按模板的文本框宽度重新排一次，并**渲染核对没有内容越界**（不要只看编辑视图）。

## 4. 内容要点（便于逐条核对）

| 块 | 一句话 |
|---|---|
| 问题 | 边缘视觉的两个硬约束：延迟与带宽；同一网络在 PL 上 125.5 ms，在双核 A9（666 MHz）上慢一个数量级 |
| 架构 | OV5640 → 自研采集 RTL → DPU → PS 侧双线程推流；**两个时钟 100/200 MHz 必须精确 2 倍** |
| 结果 | 1025×720 @ 7.4–7.5 fps、框更新 3.9/s、推理 191–193 ms、377 KB/s、WNS +0.718 / WHS +0.051 ns、LUT 70.2% / BRAM 88.2% / DSP 96.4% / Slice 98.2% |
| 性能 | 帧率台阶模型 `T_total = ceil(T_proc/T_cam)×T_cam`；解耦后 2.4 → 7.5 fps（+208%），**比特流与资源零变化** |
| 两个难题 | ① 加速器拒绝模型 → 3 个 BD 开关（依据来自 IP 自己的生成文件）；② 输出非确定 → 2x 时钟比例必须是精确 2 倍 |
| 正确性 | RTL 仿真 `fw_tb` 通过；8/8 图 `identical=1` 逐字节一致；8/8 命中标准答案 |

**有一处刻意保留的诚实表述**（海报右下角）：

> *Stated plainly: the simulation covers the custom RTL only — not the DPU internals, and not the
> PS-side software. The strongest correctness evidence is the golden comparison on real hardware.*

即：**仿真只覆盖自研 RTL**。把边界说清楚，比让"有仿真"听起来像"全链路仿真"更可信。
