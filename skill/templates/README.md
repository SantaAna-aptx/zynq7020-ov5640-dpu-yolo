# templates/ —— 案例模板

"案例模板"指的是：**一个可以整套搬到另一个项目上的做法**，包括它的结构、参数、取舍理由，
以及最重要的 —— **它在什么条件下不成立**。

模板和踩坑清单的区别：

- **踩坑清单**回答"我遇到这个现象该查什么"
- **案例模板**回答"我要做这件事，应该怎么搭，以及为什么这么搭"

所以每个模板都刻意写清了**被否决的替代方案与否决理由**。
只有结论的模板没有复用价值 —— 因为换个场景，结论可能就反过来了；
而**理由**是可以迁移的。

## 为什么案例模板里要写"被否决的方案"

本项目的解耦模板里列了 **9 个被评估并否决的方案**，每个都带否决理由。
这一节的价值在事后被反复验证：

- **"降 JPEG 质量换速度"被实测否定** —— 预期省 20 ms，实测只省 1.2 ms。
  原因：JPEG 的耗时主要在色彩转换、DCT 与量化表，**质量参数只影响熵编码**。
  如果只写"我们保持了质量 72"，别人会以为这是审美选择，而不知道**这条路根本走不通**。
- **"提高相机帧率"被推迟** —— 理由不是"做不到"，而是"缩短曝光会让图像变暗、
  增加暗部噪声，反而降低识别率"。这是一个**跨领域的权衡**，
  单看"帧率提高 4 倍"是看不出来的。
- **"加速器超频"被否决** —— 理由是**历史时序数据**（该时钟域在更高频率下的 WNS 是负数）
  加上**资源已见底**（DSP 96.4%、BRAM 87.9%，没有余量）。

**这些否决理由才是模板里最值钱的部分。**
它们把一个"我们这么做了"的陈述，变成了"在这个约束条件下，为什么只能这么做"的推理。

## 每个模板的固定结构

1. **适用场景 / 使用方法 / 失效条件**（表格，放在最前面）
2. **问题或目标的量化描述** —— 带数字，不带形容词
3. **方案结构** —— 图 + 关键参数 + 每一步的作用
4. **为什么这样是对的** —— 论证，不是断言
5. **代价与取舍** —— 这个方案付出了什么
6. **被评估并否决的替代方案** —— 含否决理由
7. **验收数据** —— 改进前后对比、预测与实测的偏差
8. **可迁移的方法论** —— 从这个案例里能拿走的一般性做法

第 8 节是刻意加的：一个模板如果只教"怎么解耦"，换个领域就没用了；
但如果它教"**先量化再动手，把慢的部分移出关键路径，并保留回滚路径**"，就哪都能用。
