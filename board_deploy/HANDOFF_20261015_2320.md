### 根因 1：DPU 特性开关设错 → 模型被拒载

现象：`[DNNDK] DPU configuration mismatch ... parameter: Conv+Leakyrelu, DPU kernel: Enabled, DPU IP: Disabled.`

统一工程 BD 里 `dpu_eu_0` 把三个"主开关"设错了（IP 的其余特性都由它们推导，
推导公式在 `dpu_ip/dpu/gui/dpu_eu_v3_0.gtcl`）：

| 参数 | 原值 | 改为 | 影响 |
|---|---|---|---|
| `CONV_RELU_ADDON` | 2 | **3** | `CONV_LEAKYRELU=1` 且 `CONV_RELU6=1`，`DWCV_RELU6` 跟着变 1 |
| `POOL_AVERAGE` | 0 | **1** | Average Pool Enabled |
| `LOAD_AUGM` | 0 | **1** | Channel Augmentation Enabled |

修复后 `dexplorer -w` 六项全 `Enabled`（**已在板子上实测确认**）。

### 根因 2：`dpu_2x_clk` 不是 `m_axi_dpu_aclk` 的整数 2 倍 → 计算非确定

修好特性后特性表对了，但结果是**非确定的垃圾**：

```
Class name: carrot  conf=0.679179  box=(-1510,-5858)-(1997,6246)   ← 15 个荒谬类别
DETERM_CHECK: run1=-8615966 run2=-9379926 identical=0              ← 每次跑都不同
BOXES: raw=0 after_nms=0
```

`identical=0` 是关键线索（D3 基准是 `identical=1`）。DPU IP 自己生成的约束文件
`dpu_ip/dpu/ttcl/timing_clocks_xdc.ttcl` 写着：

```tcl
# constrains for DDR-DSP #
set clk_2x [get_clocks -of_objects [get_ports dpu_2x_clk     ]]
set clk_1x [get_clocks -of_objects [get_ports m_axi_dpu_aclk ]]
set_multicycle_path 2 -setup -start -from $clk_2x -to $clk_1x
```

`multicycle 2` 的前提是两时钟成**精确 2 倍**关系 —— 这是 IP 内部 2x 域状态机
对 1x 域 pacing 的**功能假设**，不只是时序约束。

| | `m_axi_dpu_aclk` | `dpu_2x_clk` | 比例 |
|---|---|---|---|
| 统一工程（算错） | 100 MHz | **150 MHz** | ❌ 1.5 倍，两时钟非整数倍 → 相位持续漂移 |
| **修正后** | 100 MHz | **200 MHz** | ✅ 正好 2 倍 |

修法：`set_property CONFIG.CLKOUT3_REQUESTED_OUT_FREQ 200 [get_bd_cells clk_wiz_0]`
→ MMCM 自动解算为 `MULT_F=20 / DIVIDE 10,10,5`（VCO=1000MHz），生成的 HDL 注释确认
`clk_out3___200.000`。`clk_out3` 全设计只驱动 `dpu_eu_0/dpu_2x_clk` 和
`rst_300/slowest_sync_clk`，对其他部分零影响。

### 排除了一个嫌疑

摄像头走 `S_AXI_HP3`（FCLK_CLK0 = 50 MHz 域），DPU 走 `S_AXI_HP0/1/2`（100 MHz 域），
**端口分开**，摄像头约 44 MB/s 的写入对 DDR3 带宽压力很小 →
"摄像头抢 DDR 带坏 DPU 访存"的可能性很低。

## 构建踩过的坑（下次改 BD 一定要记住）

1. **改完 BD 参数不要直接 build** —— IP 会被锁，`synth` 会**静默沿用旧网表**：
   `WARNING: [Project 1-577] ... the IP is locked ... out-of-date checkpoint will be used`。
   必须先 `upgrade_ip` 清锁（`diagnose_ip_lock.tcl`），再 `generate_target`。
2. **`upgrade_ip` 可能重置 IP 配置** —— 所以解锁之后必须**重新校验** DPU 那三个参数
   （`fix_clk2x_and_build.tcl` 里带了这道保险，不满足就 `exit 1` 拒绝构建）。
3. **`CLKOUT3_ACTUAL_OUT_FREQ` 在 `set_property` 之后是空的**，要等 `generate_target`
   之后才有值。别在读不到时误判失败（今天因此白跑了一轮）。
4. **确认 clk_wiz 没用旧缓存**：看生成的
   `design_1_clk_wiz_0_0.v` 注释里的 `// clk_out3___200.000` 和 `.xci` 里的
   `C_MMCM_CLKFREQBOUT_MULT_F`。`Using cached IP synthesis design` 本身是正常的。
