# OV5640 调试状态 — 2026-10-05 会话（终审判决：模块死/无电，等换模块）

## 最终判决（diag2 + diag2c 双向时钟注入实验）

自制最小诊断 bit（纯官方 IP：÷16 分频 9.375MHz 时钟注入 + 11 根相机线 GPIO 采样 + SCCB GPIO，md5 265021f4/diag2 与 dba86eb4/diag2c，源码 build_diag2b.tcl/build_diag2c.tcl + diag2.xdc/diag2c.xdc + clk_div16.v）：
- **diag2（时钟→D20/pin8，"正确接法"）**：PCLK/VSYNC/HREF/D0-D7 全静止（30000 采样 0 翻转，恒读 0x7FF 输出三态特征）+ SCCB 全 NACK
- **diag2c（时钟→D19/pin7，"接反场景"）**：同样全静止 + 全 NACK
- **结论：无论 XCLK 打到 pin7 还是 pin8，相机模块都无任何输出、SCCB 无响应 → 接反假设排除，模块死或未供上电**
- 板侧一切已被证明正常：GPIO 环回、ACK 采样自检、SCCB 时序仿真、时钟注入两种位置、上拉实测

## 今日重大发现（颠覆之前认知）

1. **历史抓帧全是噪声，"相机成功出流"是误判**。CAP.raw（100% 非零）渲染出来是绿色垂直条纹噪声；CAMERA_LIVE.bmp 上半是粉紫噪声下半是洞。教训再次验证：只有渲染目视 + FDMA 帧号增长 + SCCB 读回 ID 三证齐全才算数。
2. **P1-A 比特流里没有 0x43010000 的 VDMA**。xparameters.h 实测地址：VDMA 唯一实例 0x43000000（HDMI 读通道）、uifdma_dbuf 0x43C00000、GPIO SCCB=0x41210000 / RST=0x41200000 / CTR=0x41220000。相机数据由 PL 内 uiFDMA **自动**写 DDR 0x08000000，**无需也不能用软件启动**。之前会话所有 `devmem 0x430100xx` 的"VDMA S2MM 配置"全是写空，读回的 0x00010000 是空总线幻影。
3. **判定传感器真出流的硬指标**：`devmem 0x43C00000`（uiFDMA 帧号寄存器）两次读数应随时间增长（~30fps → 6 秒 +180）。**判定 SCCB 配置真生效**：用 `sccb_read_id.py` 读 0x300A/0x300B 应得 0x56/0x40，且回读 0x4300=0x61、0x3824=0x02、0x3035=0x41、0x3036=0x69 与写入一致。此脚本还逐字节采样第 9 位 ACK——第一次能知道写入是否被相机接受。
4. **老师工程从未检查 ACK/ID**（sccb_iic.c 无读函数，纯盲写）；rstn GPIO 是 FPGA 内部帧门控（释放后等 5 个 vsync 出数据），不是相机复位脚；相机无 PWDN/RESET 接线进 FPGA。
5. **"简单版简单在哪"（compare_projects.py 已跑完）**：简单版相机路径 = uiSensorRGB565 → **标准 AXI VDMA_1 S2MM（0x43010000，软件配置）** → DDR，软件 92 行；P1-A = uiSensorRGB565 → rgb24to32 → **自定义 uiFDMA（PL 自动）** → DDR + 按键拍照存 SD（中断 + xlconcat + button_led）。XDC 差异仅 button_led[0..1]（T19/K14）。**注意：0x43010000 的 devmem 序列属于简单版比特流，在 P1-A 上无效。**
